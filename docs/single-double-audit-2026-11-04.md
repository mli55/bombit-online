# 单人原版对照与双人复查（2026-11-04）

这份报告替代早先只验证 60 Hz 联机步进的结论。当前单人模式不是 4399 Flash 的完整复刻。以下逐项区分已对齐的规则、此次修复的错误和仍然存在的差异，不把“测试通过”当作“所有玩法完全一样”。

## 基准与验证方法

- 基准为同日获取并反编译的 [4399 Q版泡泡堂](https://www.4399.com/flash/3881.htm) `game.swf`，SHA-256 `a2b4cc65115e4b6eb813962d80e91f1e65746a91f27e91d5e86fa1963ed5b54d`，35 FPS。
- 逐项复查 `DefineSprite_554/frame_1/DoAction.as` 中的 `putBomb`、`bombExp`、`pushBomb`、`putSpecial`、移动、道具、AI 和 `gameover`；并检查 frame_2 初始化、地雷时间轴、手榴弹三方向时间轴、计时器和关卡配置。来源文件保留于忽略目录 `.local/4399-audit-2026-11-04/`，详见[原始核验记录](settings-audit-2026-11-04.md)。
- **单人时钟测试调用原生 `game.update`**，输入 30、60、120、144、240 Hz 和运行中 120→30 Hz 的显示时间戳；不调用联机步进 API。每档放置 1、10、100 颗炸弹，测放置到爆炸、火焰结束、对局时钟和原生暂停按钮。显示时间戳是受控测试输入，不代表对不同实体显示器的实拍。
- 单人规则测试通过真实引擎拾取鞋子、释放六种武器、推进冻结/减速、结算得分；简单/普通/困难 AI 各运行 20 秒原生逻辑。
- 碰撞与投掷测试分别运行原生单人、原生本地双人引擎、双人联机，共 96 个场景。双人联机另在独立浏览器重放，并比较全部测试帧的状态摘要汇总。
- 两个真实浏览器通过菜单、键盘和 WebSocket 测试线上模式：选人、开始、输入、暂停、断线 5 秒、重连、切换难度、返回菜单。原生本地双人是引擎级覆盖；网站的 Multiplayer 入口仍然是联机模式。
- [测试数据](single-double-audit-results.json) 保存上述结果。规则参数的来源比较不等于两个引擎逐像素、逐帧或所有事件组合的等价证明。

## 此次发现并修复

### 显示帧率改变单人引信

旧引擎按 60 Hz 调度逻辑，却在每个逻辑步中使用最近一次显示刷新的 `elapsedMS`。120 Hz 显示每次约 8.33 ms，但每秒只约 60 个逻辑步，因此引信被拉长；当场景变重、显示降到 60 Hz 时，引信又缩短，看起来越放越快。

同一个原生引擎、同一颗炸弹的修复前测量：

| 显示刷新输入 | 修复前爆炸时间 |
| --- | ---: |
| 30 Hz | 约 1.733 秒 |
| 60 Hz | 约 1.733 秒 |
| 120 Hz | 约 3.433 秒 |
| 144 Hz | 约 4.111 秒 |
| 240 Hz | 约 6.858 秒 |

`simulation-clock.js` 统一每个逻辑步为其实际模拟步长；30 Hz 时允许消费两个 60 Hz 步，沿用每次最多约三步的时间上限，避免原引擎的步数波动启发式丢掉有效帧。修复后 18 组原生测试的首爆约 **1.701–1.742 秒**，差值位于显示/逻辑帧边界内；目标仍为 **60/35 = 1.714286 秒**。暂停不累计引信，恢复后不补算暂停时间。

这与上一轮“连锁时列表删除导致同帧重复更新”的问题是两个独立问题。之前对重复更新的修复仍保留；之前的固定 60 Hz 验证未覆盖高刷新率单人时钟，是上次验证范围不足。

### 踢不动的炸弹被碰一下就炸

Flash 的 `pushBomb` 先确认炸弹前方一格没有墙、砖或炸弹，才允许踢动。HTML5 旧实现直接进入踢动状态，第一帧遇阻立即引爆。

`bomb-collision-fixes.js` 现在拒绝被墙、砖、炸弹和边界挡住的踢动。没有踢弹能力的角色碰弹也不引爆。有效踢动之后遇到障碍，以及火焰命中造成的连锁，仍然可以提前引爆，这是原版的规则。

### 黄色投掷武器标记、落点与暂停

该武器在代码中叫 `GRENADE`。原标记只在一个坐标轴改变时刷新，因此横向瞄准时上下移动、纵向瞄准时左右移动，会遗留旧位置；被墙拒绝的投掷还会保留旧目标，随后向边界投掷可能复用旧格子。

`grenade-fixes.js` 让标记和投掷共用前方两格的目标计算，每次刷新两个坐标；墙或越界目标不消耗次数；发射后目标固定，不随角色移动。原来投掷动画的完成回调也会在暂停时引发爆炸，现在动画和落地事件由同一个模拟时钟推进。落点中心加相邻四格的十字伤害、清理及暂停均经过原生单人/双人及联机测试。
